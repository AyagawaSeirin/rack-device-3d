# 从Dell C6420制作中提炼的执行经验

这些是已发生的制作问题与修复经验，不是对尚未制作的Cisco模型的通过报告。完整动作要求已写入TASK-PROMPT.md，该提示词不依赖阅读本文件才能执行。

| 实际问题 | 判断与修复经验 | Cisco任务中对应的要求 |
|---|---|---|
| 初版外观被用户认为动画化 | 重新建立写实钣金、材料、接口和细节，不把数量/包围盒正确当作外观合格 | 六面与斜视、材质和特写都要与真实设备对照 |
| 原始NSL前照是塑料填充件，用户要求正常盘架 | 用户明确意图优先；补找真正正常托架实拍，移除所有假盘位 | 默认正常可见端口笼/暗腔，不能用假堵头或黑矩形代替结构 |
| 相似设备、可选PSU/NIC混在商家图中 | 按实际型号与配置逐图采用/排除；同张库存图不算多个独立证据 | 禁止FX2/FX2-E/9336PQ混用；风扇模块与内部转子分开计数 |
| 797.3mm被误读成完整前后总深 | 官方安装基准和突出件必须分清；Dell总深是另行正确累计所得 | Cisco规格写Depth with Handles，不能再额外叠加同一把手长度 |
| 薄金属和粗颗粒反射看起来像花岗岩，黑塑料发灰 | 降低微纹理幅度、按物理尺度设UV，调整中性照明和粗糙度 | 不通过极端曝光/发光掩盖形状；对比Material Preview与最终渲染 |
| 前部穿孔金属出现星状反光 | 平面分裂法线曾最大偏离约22.26°；仅校正孔板平面法线后星状反光消失 | 不对所有面盲目平滑；尤其检查挂耳孔边、大平面与倒角的法线 |
| 低清斜拍标签在放大/强对比后出现拖影 | 换用更清晰真实照片，仅做明确的投影/烘焙，保留小字分辨率限制 | 尽早检索Cisco铭牌/端口编号特写，不用AI编造小字 |
| 当前视口标签正确，重开文件却变黑块 | 删除UV层后持有的RNA引用失效，节点仍指向不存在的层；重新建层并设名修复 | 检查所有UV引用存在，保存重开及GLB重导入再次核验 |
| 曲线转网格和文字转换产生边界/退化面 | 封口、去重、清退化、重算法线；必要时显式三角化 | 真实体与印刷平面分开检查；不能把正确通孔一并补死 |
| 整圈截图里输入已发送，但画面滞后 | 确认真实视口焦点、等待重绘、核对首末姿态 | 按键计数/文件名不等于拍到了指定角度；q与-q同姿态 |
| 鼠标停在着色模式栏，KP_6没有旋转模型 | 查询到视角完全没变，停止错误记录，点击3D视口后重录 | 挂耳复查和完整转台都先验证一次真实旋转有效 |
| RDP调整分辨率后坐标比例变化 | 截图原生2560×1440可能显示成2048×1152，坐标需要换算 | 每次坐标操作前取新图，重新确认当前原生像素尺寸 |
| MCP180秒超时，但模型保存后来成功 | 先核对文件mtime/大小、窗口和新连接，不重复创建几何 | 大操作分段；超时后区分仍在执行、已完成、真实失败 |
| 在MCP回调内打开.blend后screen为None | 后续操作分到新调用，重新取得当前窗口/场景 | 不沿用打开文件之前的对象、材质和UI上下文引用 |
| 只检原.blend无法发现导出后的错误 | 实际导出GLB、独立场景重开，再查尺寸、UV、法线、Alpha | 挂耳孔必须在GLB里重复隔离/装配检查，不能只验原模型 |
| glTF拆分同位置顶点导致诊断误判 | 在诊断副本按小容差焊接再查闭合，不修改正式模型 | 区分UV/法线拆点与真正裂缝，不为修“假缺面”破坏硬边 |
| 工程迁入仓库后脚本仍写旧工作台路径 | 保留原证据字节，适配外部脚本根路径，记录迁移SHA256 | 从开始统一PROJECT_ROOT、相对路径和贴图打包 |
| 全部过程资产约2.7GB，部分.blend超过普通Git限制 | 先限定LFS属性再暂存；36个大型文件通过LFS上传，虚拟环境不提交 | 保护全套模型/资料/QA，避免提交缓存和先产生超大普通Git blob |

挂耳的“透明空洞”应进一步明确：几何上切穿并有孔壁，金属本体OPAQUE；背景是否可见取决于孔后真实遮挡。隔离挂耳时可期待空孔Alpha=0，正常装配有螺钉/机身时则应正确遮挡。不能把所有孔中心一律设透明，也不能用双面渲染隐藏反法线。
